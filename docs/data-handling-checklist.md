# Meridian Markets: Capstone Data Handling Checklist

**For:** MSBA student team members and Meridian staff supporting the project.

**Rules agreed for this project:**

- Students receive aggregated summaries only.
- Customer and employee data, including excerpts, must never enter AI tools.
- The brief permits AI use of sales totals by store and week and store attributes. Aggregating other data does not automatically make it eligible for AI use.
- A designated Meridian owner approves each extract; a student lead verifies it on receipt.
- Meridian approves every release outside the project team.

| Done | Action | Responsible person | Completion record |
|---|---|---|---|
| **1. Agree before requesting data** | | | |
| ☐ | Confirm the NDA is signed and both teams understand the handling requirements. | Meridian owner and student lead | NDA confirmation and team acknowledgment |
| ☐ | Name the Meridian extract approver, student lead, system owners, and contact for data issues. | Both teams | Contact list |
| ☐ | Specify the summaries needed, including fields, time periods, and aggregation levels. Request only data needed for the agreed analysis. | Student lead; Meridian owner approves | Approved data request |
| ☐ | Identify approved Meridian and university systems, authorized users, transfer methods, and which data may move between systems. | Both teams | Approved handling agreement |
| ☐ | Set a deadline and process for returning or deleting data, including copies, backups, and version history. | Both teams | Retention and deletion agreement |
| **2. Prepare and transfer each extract** | | | |
| ☐ | Prepare aggregated summaries without individual customer or employee records or identifying details. Agree on rules for withholding small groups that could expose individuals. | Meridian owner | Extract review record and aggregation rules |
| ☐ | Approve the extract’s contents and intended use before releasing it. | Meridian owner | Approval identifying the extract version |
| ☐ | Transfer the approved extract through the agreed channel to an approved location. | Meridian sender | Transfer record |
| ☐ | Check that received files, fields, and aggregation levels match the approval. If unexpected restricted data appears, follow Stage 5. | Student lead | Receipt check |
| **3. Control storage and access** | | | |
| ☐ | Give access only to approved project members who need it. Check sharing settings before making data available. | Owner of each system | Access list and sharing check |
| ☐ | Keep working files and exports in approved locations. Follow the agreed rules for transfers between Meridian and university systems. | Everyone handling data | File inventory and transfer records |
| ☐ | Remove access when someone leaves the team or no longer needs the data. | Owner of each system | Updated access list |
| **4. Analyze data and use AI appropriately** | | | |
| ☐ | Keep analysis within the agreed capstone scope. Obtain Meridian approval before using data for another purpose. | Student analysts | Analysis scope and any additional approval |
| ☐ | Before entering project data into an AI tool, check the prompt, attachments, and excerpts. Use only permitted store-by-week sales totals and store attributes. | Person using AI | AI-use log identifying the data used |
| ☐ | Keep customer and employee data out of AI tools. For other categories not explicitly permitted by the brief, obtain written clarification from Meridian before AI use. | Everyone handling data | Written clarification, where applicable |
| ☐ | Record sources, extract dates, cleaning steps, and data limitations. Check whether the POS migration affects comparisons over time. | Student analysts | Data preparation and quality log |
| **5. Respond to unexpected restricted data** | | | |
| ☐ | Stop using the affected extract, restrict access, and notify the Meridian owner. Do not include restricted contents in the notification. | Person discovering the issue | Issue record without restricted contents |
| ☐ | Follow Meridian’s instructions for cleanup and replacement. Verify the replacement extract before resuming work. | Meridian owner and student lead | Cleanup confirmation and replacement check |
| **6. Review and share results** | | | |
| ☐ | Check reports, dashboard views, drill-downs, downloads, and screenshots for restricted information or small groups that could expose individuals. | Student lead | Output review record |
| ☐ | Obtain Meridian approval for every release outside the project team, including class presentations, portfolio materials, and dashboard links. Specify the audience, including for board materials. | Student lead requests; Meridian owner approves | Approval identifying the exact version and audience |
| ☐ | Share the approved version only with the approved audience. Check link permissions and download settings. | Person sharing | Release record and sharing check |
| **7. Close the project** | | | |
| ☐ | Obtain Meridian approval for any final deliverables students or the university will retain. | Student lead requests; Meridian owner approves | Approved retention list |
| ☐ | Return or delete data and working copies by the agreed deadline. Follow the agreed process for backups and version history. | Both teams, for their systems | Return or deletion confirmation |
| ☐ | Remove access and shared links that are no longer needed. | Owner of each system | Closeout confirmation |

**Before use, both teams still need to fill in:** named owners, approved systems and transfer methods, aggregation rules, and the return/deletion deadline.
